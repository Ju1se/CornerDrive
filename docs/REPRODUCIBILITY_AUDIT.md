# Reproducibility Audit

Date: 2026-05-25

This audit evaluates CornerDrive as a research reproduction package: a reviewer
should be able to install the environment, prepare public data, rerun the
canonical scripts, rebuild paper-facing tables, and check key values against a
tolerance manifest.

## Reviewer Protocol

Run from the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/prepare_data.py --download-torchvision
bash scripts/reproduce_all.sh main
bash scripts/reproduce_all.sh appendix
REAL_SOURCES=mnist,fashionmnist bash scripts/reproduce_all.sh real-gradient
python scripts/make_paper_tables.py
python scripts/check_expected_results.py
bash scripts/verify_all.sh
```

For the full thesis setting, prepare FEMNIST/LEAF under `data/real/femnist/`
and run:

```bash
bash scripts/reproduce_all.sh all
```

`all` reruns real-gradient, synthetic ALG, appendix stress experiments, table
generation, and expected-result tolerance checks.

## Remaining Limitations

- FEMNIST/LEAF is not vendored. A long-term archival package should include
  dataset acquisition instructions, exact LEAF preprocessing revision, and data
  checksums or a DVC manifest.
- CPU execution is the tested reproducibility target. CUDA can accelerate runs,
  but bitwise equality is not claimed across GPU drivers or hardware.
- Full real-gradient reproduction is computationally heavier than the synthetic
  smoke path. Reviewers should use `REAL_SOURCES=mnist,fashionmnist` first when
  validating setup before preparing FEMNIST.
- Frontend development tooling still has audit debt in the Vite/ESLint chain.
  Production dependency audit is clean; a dev-tooling major-version migration
  should be handled separately.
- Local ignored `results/` directories may contain historical experiments. The
  current evidence is defined by `scripts/reproduce_all.sh`, `configs/`, and
  `artifacts/tables/table_provenance.json`, not by every directory present on a
  developer machine.

## Maintenance Rules

1. Any new paper-facing metric must be generated by a script under `scripts/`.
2. Add new canonical experiment settings to `configs/`.
3. Add or update expected high-signal values in `results/expected_results.csv`.
4. Regenerate tables with `scripts/make_paper_tables.py`.
5. Run `scripts/check_expected_results.py` before citing generated values.
6. If thresholds are retuned, create a new calibration manifest and a new
   held-out seed range rather than overwriting the existing record.
